# 내 포켓몬 진화 시스템 — 설계 문서

- 작성일: 2026-08-02
- 상태: 설계 승인됨, 구현 계획 대기

## 배경 및 목적

어린이 사용자의 재방문/몰입도를 높이기 위해, "나만의 포켓몬을 골라 퀴즈를 풀며 키우고 진화시키는" 코어 루프를 추가한다. 기존 퀴즈(실루엣/초성/울음소리)와 도감은 그대로 두고, 그 위에 애착·수집·성장의 동기를 얹는다.

성공 기준:
- 퀴즈를 풀 이유가 하나 더 생긴다 (내 포켓몬을 키우기 위해).
- 실패해도 벌칙이 없다 (오답으로 포인트가 깎이거나 스트릭이 끊겨도 좌절감을 주지 않는다).
- 계정/로그인 없이, 기존 `localStorage` 패턴만으로 동작한다.

## 범위 (Phase 구분)

한 번에 구현하기엔 범위가 넓어, 아래 3단계로 나눈다. 이 문서는 세 Phase를 모두 설계하지만, 구현 계획(다음 단계)은 Phase별로 나눠 진행할 수 있다.

- **Phase 1 (핵심)**: 진화 체인 데이터, 내 포켓몬 선택/진화/포인트 시스템, 진화 순서 퀴즈, 홈 화면 통합.
- **Phase 2 (내 포켓몬 화면 부가 기능)**: 별명 짓기, 완성 카드 공유, 쓰다듬기 인터랙션.
- **Phase 3 (독립적 참여 유도 기능)**: 만난 포켓몬 도장판(도감 진행률), 타입 마스터 배지, 오늘의 퀴즈, 부모님용 요약.

Phase 2·3은 Phase 1의 데이터 모델에 필드를 더 얹는 방식으로 설계해 서로 충돌하지 않게 한다.

## Phase 1 — 내 포켓몬 진화 시스템

### 데이터: 진화 체인 캐싱

`scripts/fetch-pokemon-data.mjs`가 각 species의 `evolution_chain` URL을 이미 받아오고 있으나(`evolutionChainUrl`), 실제 체인 내용은 저장하지 않는다. 이를 확장해 `public/data/pokemon.json`의 각 항목에 다음 필드를 추가한다.

```json
"evolutionStage": 1,
"evolvesFrom": null,
"evolvesTo": [
  { "id": 2, "minLevel": 16 }
]
```

- `evolutionStage`: 해당 진화 체인에서 몇 번째 단계인지 (1~3).
- `evolvesFrom`: 이전 단계 포켓몬 id, 없으면 `null`.
- `evolvesTo`: 다음 단계 목록. 이브이처럼 여러 갈래면 배열 원소가 여러 개.
- `minLevel` 등 원작의 레벨/친밀도/돌 조건 값은 참고용으로만 저장하고, 실제 진화 트리거로는 쓰지 않는다(아래 포인트 방식으로 대체).
- 특정 species의 evolution-chain fetch가 실패하면 `evolvesTo: []`로 두고 경고 로그만 남긴다(빌드를 막지 않음).

### 내 포켓몬 후보 및 선택

내 포켓몬으로 고를 수 있는 후보 = `evolutionStage === 1 && evolvesTo.length > 0` 인 포켓몬 전체. (전설/신화 포켓몬은 대부분 진화가 없어 이 조건만으로 자연히 제외됨.)

첫 실행 시(또는 완전 진화 후 "새 친구 고르기" 선택 시) 이 후보 목록에서 검색/타입 필터가 가능한 선택 화면을 보여준다 (기존 `Dex`의 검색·필터 UI를 재사용).

### 저장 구조 (localStorage)

기존 `pokemonQuiz.gen1Only` 패턴과 동일하게, 접근 실패 시(시크릿 모드 등) 조용히 무시하는 방어 코드를 그대로 적용한다.

```json
// key: "pokemonMine.v1"
{
  "starterId": 1,
  "nickname": "몽몽이",
  "currentStageId": 1,
  "history": [1],
  "pointsSinceLastEvolution": 40,
  "lifetimePoints": 340,
  "pendingEvolution": false,
  "collection": []
}
```

- `starterId`: 처음 고른 포켓몬 id (기록용, 로직에는 안 씀).
- `currentStageId`: 지금 형태의 포켓몬 id.
- `history`: 지금까지 거쳐온 진화 단계 id 배열 (연출/컬렉션 화면에 사용).
- `pointsSinceLastEvolution`: 다음 진화까지 누적 중인 포인트.
- `lifetimePoints`: Phase 3 배지 계산 등에 쓸 전체 누적치.
- `pendingEvolution`: 임계값을 넘겨서 홈 화면에서 진화 연출을 재생해야 하는 상태인지.
- `collection`: 완전 진화 후 "졸업"시킨 이전 포켓몬 id 목록.

내 포켓몬이 없으면(`starterId` 없음) 관련 UI는 전부 "내 포켓몬 고르기" 유도 상태로 표시한다.

### 포인트 적립

기존 퀴즈들은 이미 정답 시 `Math.max(30 - hintLevel * 10, 10)` 점수를 계산하고 있다. 이 값을 그대로 재사용해 각 정답마다 `pointsSinceLastEvolution`과 `lifetimePoints`에 더한다. **오답으로 포인트를 깎거나 초기화하지 않는다.**

포인트 소스는 실루엣/초성/울음소리/진화순서 퀴즈 4종 전체 (특정 종에 한정하지 않음 — 퀴즈는 랜덤 출제되므로 "내 포켓몬이 나올 때만" 포인트를 주면 사실상 거의 못 얻게 됨).

도감 상세 페이지 열람(Phase 3의 "만난 포켓몬" 스탬프)은 이 포인트에 영향을 주지 않는다 — 탐색과 퀴즈 실력을 같은 지표로 섞지 않기 위함.

### 진화 임계값 & 타이밍

- `EVOLUTION_THRESHOLD = 200` (튜닝 가능한 상수).
- `pointsSinceLastEvolution >= 200`이고 현재 단계에 `evolvesTo`가 있으면: 임계값을 **초과한 만큼은 다음 주기로 이월**(예: 190점에서 +30 획득 시 220 → 다음 단계로 진화하고 새 주기는 20부터 시작), `pendingEvolution = true`로 표시.
- 진화 자체는 **퀴즈 화면 안에서 바로 재생하지 않는다.** 정답 화면에는 "포인트 +20 · 내 포켓몬이 진화하려고 해요!" 정도의 작은 배지만 노출.
- 실제 진화 연출(전체 화면, 반짝임 애니메이션 + 실루엣 → 새 모습 전환)은 `pendingEvolution === true`인 상태로 **홈 화면에 진입했을 때** 1회 재생하고, 재생 후 `pendingEvolution = false`로 되돌린다.
- 분기 진화(예: 이브이 → 여러 갈래): `evolvesTo.length > 1`이면 자동으로 하나를 고르지 않고, 연출 중간에 "어떤 모습으로 진화할까요?" 선택 화면(각 분기의 실루엣 카드)을 보여주고 아이가 직접 고른 것으로 `currentStageId`를 정한다.

### 최종 진화 이후 — 졸업 흐름

`evolvesTo.length === 0`인 단계에 도달하면 최종 진화로 간주하고 축하 연출 후 두 가지 버튼을 제시한다.

- **계속 보기**: 아무 상태 변화 없음, 홈에 완성된 포켓몬으로 계속 표시.
- **새 친구 고르기**: 현재 `currentStageId`를 `collection` 배열에 추가하고, `starterId`/`currentStageId`/`history`/`pointsSinceLastEvolution` 등을 초기화해 선택 화면으로 돌아간다. `lifetimePoints`와 `collection`은 초기화하지 않는다(Phase 3 배지·기록용으로 계속 누적).

### 신규 퀴즈: 진화 순서 맞추기

퀴즈 허브에 이미 "준비중"으로 자리만 있는 `evolution` 모드를 실제로 구현한다.

- 출제 대상: `evolvesTo.length > 0`인(즉 진화 체인이 있는) 포켓몬 중 랜덤. 해당 체인의 2~3단계 아트워크를 섞어서 제시.
- 상호작용: **탭한 순서대로 정렬** (드래그 앤 드롭 대신). 카드를 탭할 때마다 순번 배지(①②③)가 붙고, 마지막 카드를 탭하면 자동 채점.
- 힌트: 기존 퀴즈들과 같은 패턴 재사용 — 1단계: 타입 힌트, 2단계: 설명(도감 문구) 힌트.
- 점수 계산식은 다른 퀴즈와 동일(`30 - 힌트단계×10`, 최소 10)하게 맞춰 포인트 시스템과 자연히 연동되게 한다.
- `QuizHub.jsx`의 `MODES` 배열에서 `evolution` 항목의 `ready: false`를 `true`로 바꾸고 `/quiz/evolution` 라우트 및 `EvolutionQuiz.jsx` 페이지를 추가한다.

### 화면/내비게이션 변경

- 하단 탭(홈/도감/퀴즈)은 그대로 유지한다 (5개 이하 권장 가이드, 지금도 딱 맞음).
- **`Home.jsx`를 "내 포켓몬" 중심으로 재구성한다.** 기존의 "포켓몬 도감"/"퀴즈 바로가기" 큰 카드 2개는 하단 탭과 완전히 겹치는 기능이라 제거하고, 그 자리를 내 포켓몬 섹션이 대신한다.
  - **내 포켓몬이 없으면**: "나만의 포켓몬을 만나보세요!" 같은 문구와 함께 스타터 후보 미리보기 + "포켓몬 고르러 가기" 버튼을 큼직하게 배치해 첫 방문자가 자연스럽게 선택 흐름으로 들어가도록 유도한다. 버튼은 `/mine/choose`(스타터 선택 화면)로 이동.
  - **있으면**: 아트워크(실사, 실루엣 아님), 별명, 다음 진화까지 진행바(`pointsSinceLastEvolution / 200`)를 홈 화면 자체의 메인 콘텐츠로 보여준다. 탭하면 `/mine` 전용 화면으로 이동.
  - 앱 소개 문구/저작권 안내는 내 포켓몬 섹션 아래에 축약된 형태로 유지한다.
- `/mine/choose` (스타터 선택) 화면: `evolutionStage === 1 && evolvesTo.length > 0` 조건으로 필터링한 후보 목록을 기존 `Dex`의 검색·타입 필터 UI 패턴으로 보여주고, 하나를 고르면 `pokemonMine.v1`을 초기화한다.
- `/mine` 화면 구성: 위 정보 + 진화 히스토리 스트립(`history` 순서대로 작은 썸네일) + (완전 진화 시) 졸업 갤러리(`collection`) 링크.

## Phase 2 — 내 포켓몬 화면 부가 기능

이 항목들은 `/mine` 화면에 곁들이는 형태로, Phase 1의 데이터 모델에 필드만 더 추가한다.

- **별명 짓기**: 스타터 첫 선택 시 텍스트 입력으로 `nickname` 지정(공백이면 기본 한국어 이름 사용). `/mine` 화면에서 언제든 재설정 가능.
- **완성 카드 공유**: 최종 진화 시 `<canvas>`로 아트워크+별명+진화 히스토리+앱 로고를 합성한 이미지를 생성. 모바일에서 Web Share API 지원 시 공유 시트 호출, 미지원 환경(데스크톱 등)에서는 이미지 다운로드로 대체. 서버 업로드 없음 — 전부 클라이언트에서 캔버스로 렌더링.
- **쓰다듬기 인터랙션**: `/mine` 화면에서 내 포켓몬 아트워크를 탭하면 CSS 바운스 애니메이션 + 해당 포켓몬 울음소리(기존 `AudioButton`/`p.cry` 재사용) 재생. 저장되는 상태 없음, 순수 즉흥 반응.

## Phase 3 — 독립적 참여 유도 기능

Phase 1의 내 포켓몬 시스템과 직접 연동되진 않지만, 같은 `localStorage` 저장 원칙을 따르는 별도 기능들이다.

- **만난 포켓몬 도장판**: `Dex.jsx` 상세 페이지(`PokemonDetail.jsx`)를 열람할 때마다 `pokemonSeen.v1` (id의 Set을 배열로 직렬화)에 기록. `Dex.jsx` 목록 상단에 "1025마리 중 n마리 만났어요" 진행바를 표시.
- **타입 마스터 배지**: `pokemonBadges.v1`에 타입별 정답 누적 수를 기록(어떤 퀴즈든, 정답 포켓몬의 첫 번째 타입 기준). 타입당 10문제 누적 시 배지 획득. 배지 목록은 `/mine` 화면 하단에 작은 스티커 그리드로 표시.
- **오늘의 퀴즈**: 하루 1회 보너스 문제. 그날 날짜를 시드로 실루엣/초성/울음소리/진화순서 4종 중 하나를 결정적으로 골라 "데일리 모드"로 실행(점수 2배). `pokemonDaily.v1`에 마지막 완료 날짜(기기 로컬 날짜 기준)와 최근 7일 완료 여부 배열을 저장. 스트릭이 끊겨도 "이번 주 n일 했어요"처럼 담담하게만 보여주고 경고/처벌 문구는 넣지 않는다.
- **부모님용 요약**: `/mine` 화면 하단에 작은 텍스트 링크("부모님이신가요?")로 진입하는 읽기 전용 패널. 오늘 푼 문제 수, 누적 정답률, 가장 좋아하는 타입(가장 많이 맞힌 타입) 등을 기존 localStorage 데이터에서 계산해 보여준다. 별도 인증 없음(아동 대상 앱에서 로그인/개인정보 수집을 피하기 위한 의도적 선택).

## 에러 처리 / 엣지 케이스

- `localStorage` 접근 불가(시크릿 모드 등): 기존 `getGen1OnlyPref`와 동일하게 try/catch로 감싸 조용히 기본값(내 포켓몬 없음/도장판 없음 등) 처리.
- 저장된 JSON이 손상되었거나 스키마가 안 맞으면: 파싱 실패 시 "내 포켓몬 없음" 상태로 취급하고 새로 시작 — 앱이 죽지 않게 한다.
- `evolvesTo`가 비어 있는데 `pendingEvolution`이 true인 경우(데이터 fetch 누락 등 방어적 상황): 진화 연출을 건너뛰고 `pendingEvolution`만 false로 되돌린다.
- 기기 시계 조작으로 "오늘의 퀴즈"를 여러 번 하는 것 등은 막지 않는다 — 팬메이드 무료 앱 범위에서 방어할 가치가 낮다고 판단.

## 테스트 전략

기존 `QuizHub.test.jsx`처럼 Vitest + Testing Library를 그대로 따른다.

- 순수 로직(포인트 누적/임계값 초과 판정/이월 계산, 분기 진화 선택, 배지 카운트, 스트릭 계산)은 컴포넌트와 분리된 유틸 함수로 작성하고 단위 테스트로 커버.
- `localStorage` 관련 함수는 기존 `getGen1OnlyPref`/`setGen1OnlyPref` 테스트 패턴(있다면)을 따르거나, 없다면 이번에 함께 추가.
- 신규 `EvolutionQuiz` 페이지는 `QuizHub.test.jsx`와 같은 수준(링크 활성화, 준비중 표시 등)으로 렌더 테스트 추가.

## 오픈 이슈 / 향후 고려사항

- `EVOLUTION_THRESHOLD = 200` 등 수치는 실제 플레이 후 튜닝이 필요할 수 있음 (구현 시 상수 하나로 빼서 조정 쉽게 유지).
- 여러 기기 이어하기(계정/동기화 코드)는 이번 범위에서 제외하기로 결정함 — 필요해지면 별도 설계 문서로 다룬다.
